# GameVault Blockchain Workspace

This workspace contains the GameVault Solidity contract, Hardhat configuration,
deployment module, and smart-contract tests. It provides the on-chain authority
for GameVault game registration, developer permissions, game accounts, asset
ownership, transfers, and active/inactive state.

## Contract overview

[`GameVault.sol`](contracts/GameVault.sol) stores:

- Registered games and their developer wallets.
- Player game accounts and current owners.
- Digital assets associated with game accounts.
- Active/inactive status for games, accounts, and assets.

The contract distinguishes platform-admin operations from developer and player
operations:

- The deployer becomes the platform `admin`.
- Only the admin can register games and change game status.
- A registered developer can link accounts and add or deactivate assets.
- The current on-chain account owner can transfer account ownership.

The frontend submits wallet-authorized transactions and handles their results,
while the backend independently verifies submitted transactions, receipts,
events, and on-chain state before synchronizing application data.
The contract remains the final authority for on-chain permissions and state.

## Install dependencies

From the repository root:

```shell
cd blockchain
npm install
```

## Start a local Hardhat node

Start the local JSON-RPC network in one terminal:

```shell
cd blockchain
npx hardhat node
```

The configured `localhost` network uses:

```text
http://127.0.0.1:8545
```

The node prints disposable development accounts and private keys for local
testing. Do not use those accounts for real funds.

## Deploy GameVault locally

With the local node still running, deploy from a second terminal:

```shell
cd blockchain
npm run deploy:localhost
```

This invokes the configured command:

```text
hardhat ignition deploy ignition/modules/GameVault.ts --network localhost
```

The deployment module in `ignition/modules/GameVault.ts` deploys
`GameVault.sol`. The deployment output contains the generated contract address.
Configure that address as `GAMEVAULT_CONTRACT_ADDRESS` for the backend and
`VITE_GAMEVAULT_CONTRACT_ADDRESS` for the frontend. The backend signer must be
the contract's deployed `admin()` address.

The address is generated by each local deployment and is intentionally not
hardcoded in this document.

## Run smart-contract tests

From this directory:

```shell
npx hardhat compile
npm test
```

The `test` script is defined in `package.json` as `hardhat test`.

## Configuration and limitations

The Hardhat configuration defines:

- `localhost` at `http://127.0.0.1:8545` for the local demo.
- In-process `hardhatMainnet` and `hardhatOp` simulated networks.
- An optional `sepolia` network using the Hardhat configuration variables
  `SEPOLIA_RPC_URL` and `SEPOLIA_PRIVATE_KEY`.

The normal GameVault workflow is local-only. This workspace does not provide
cross-chain functionality, production key management, or a production
deployment configuration. Deployments to other networks require deliberate
network, account, contract-address, and backend/frontend configuration.
